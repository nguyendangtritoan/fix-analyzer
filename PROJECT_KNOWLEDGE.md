## Project Purpose
`fix-analyzer` is a privacy-first, static React application with three browser-only workflows:
- Message Analyzer parses and enriches individual FIX messages, shows multiple messages independently side by side, and optionally compares them.
- Visual Board analyzes pasted or plain-text FIX logs as correlated lifecycles with Overview, chronological Flow, and count-only field investigation.
- Text diff compares independent raw text inputs with aligned lines and character highlights.

No backend exists. Confidential imported content must remain in the current browser tab and must never be transmitted or persisted by application code.

## Stack and Runtime
- Frontend: React 19, Vite 7, Tailwind CSS 3, Lucide icons.
- Routing: native hash routing in `src/app/useHashRoute.js`; no router dependency.
- Worker: native ES module Web Worker for Visual Board parsing and retained source access.
- Tests: Node's built-in `node:test`; no test-framework dependency.
- Build output: static site (`dist/`) with base path `/fix-analyzer/`.
- Deployment: GitHub Pages workflow in `.github/workflows/deploy.yml`.

## Routes and Shared State
- Empty hash/root: Message Analyzer.
- `#/visual-board`: Visual Board.
- `#/text-diff`: Text diff, with its own input state and no dictionary controls or FIX parsing. All three workflows appear as peers in the primary navigation.
- Navigation is hash based so static hosting needs no rewrite rules.
- FIX 4.0–4.4, IMIX 2.0, and IMIXT 1.0 XML is converted to a virtual JavaScript module by Vite, eliminating runtime dictionary fetches. IMIXT 1.0 is composed with IMIX 2.0 so transport/admin and application message definitions are available together.
- Auto-detection reads `BeginString(8)` from current input/results and maps supported versioned protocol families such as `FIX.4.4`, `IMIX.2.0`, and `IMIXT.1.0`. Manual selection and local custom XML upload remain available.
- Custom dictionaries exist only in memory and are shared between both routes for the lifetime of the tab.

## Message Analyzer Behavior
`parseFixMessage(raw)` heuristic order:
1. Bracketed format detection (`<35> MsgType = D`).
2. Columnar row detection.
3. Header-guided automatic delimiter detection, with repeated-boundary inference for headerless inputs and a best-effort whitespace fallback.

`parseQuickFixXml(xml)` merges definitions into defaults and produces tags, enums, field types, message names, and recursive repeating-group schemas. Invalid XML produces a user-facing error.

`groupify` selects a `MsgType(35)` schema, renders nested repeating groups, and infers optional dictionary-missing member tags from any complete delimiter-to-delimiter instance window. All populated inputs render as independent grouped message tables side by side by default. Comparison is opt-in through the results-toolbar button and is available with at least two populated messages. Columnar display values ending in quoted raw codes (for example `EXECUTIONREPORT ['8']`) normalize to those raw codes before schema selection and comparison. `flattenForDiff` aligns group instances by delimiter tag/value identity rather than ordinal position, adds occurrence suffixes for duplicate identities, and emits visible instance-header rows. Matching tags can be highlighted with multiple colors and visual indentation can be toggled independently of grouping.

Message Analyzer's comparison toolbar only controls parsed FIX field/group comparison. Raw text comparison lives in the separate Text diff tab.

Independent messages and the Visual Board Pretty drawer share the compact navy `SingleView` panel. It uses 13px monospace text, approximately 20px field rows, a 48px right-aligned tag column, and a bounded field-name column so values retain space. Session fields are muted; dictionary enum labels precede raw codes in parentheses. Repeating groups use colored text, field-name indentation, accessible expand/collapse buttons, and small gaps between instances instead of extra instance-header rows. Instance labels remain available to screen readers. Tag buttons support keyboard highlighting and preserve matching-tag selection across messages. On narrow containers, the table scrolls locally below a 440px minimum width; long values wrap without truncation. `SingleView.css` scopes these styles; the comparison table retains its existing presentation and raw-value-first format.

Currency(15) values and slash-separated currency pairs in Symbol(55), such as `USD/NOK`, use pink text in the compact message view. Other symbols retain their regular styling. Manual row highlights use a darker rose foreground for these values to preserve contrast against the pale selected background.

Clicking a rendered value toggles a separate purple text highlight for every occurrence of that numeric tag, including repeating-group entries and other displayed messages. Tag/name clicks retain whole-row highlighting. Value highlights are shared across independent and comparison views; the drawer maintains its own set across record navigation and Pretty/Raw switches. Native value buttons support Enter/Space, pressed-state semantics, and tooltips. Value clicks do not bubble to the row; dragging to select text does not toggle highlights. Highlighted currencies temporarily use purple and restore their pink accent when cleared. Light table/selected-row backgrounds use darker purple for contrast, while compact navy panels use pale purple. `Clear value highlights` leaves row highlights and inputs intact; the main Clear action resets both kinds of highlight. State is held only in memory and never changes source data or copy/export output.

## Text Diff Behavior
The comparison card omits an explanatory banner. Its pair-selector row appears only when more than two text inputs exist, avoiding an empty header for the default two-input view.

Each input shows its name as a plain label. Hover or keyboard focus reveals a pencil; clicking the label opens a focused inline editor. Enter or blur saves the trimmed draft, Escape cancels, and keyboard completion returns focus to the rename button. Saved names update the textarea's accessible label, comparison headers, removal buttons, and pair-selector options. Empty or whitespace-only names fall back to `Text N`; custom names stay attached to input IDs when other inputs are removed. Renaming does not alter text, selected pairs, wrapping, or expanded line sections. Example and Clear reset names along with their input data. Names remain in browser memory only.

The Text diff page compares its own original pasted inputs independently of parsing/dictionaries, so ordinary log text is supported. It starts with two empty inputs; comparison updates whenever either contains text, including whitespace-only input or an empty opposite side. Example, Clear, and `+ Text` controls manage only this page's inputs. An empty workspace shows instructions. It aligns unchanged lines, pairs similar replacement lines, and highlights changed characters in light yellow, removed lines in red, and added lines in green. Changed rows have a light blue background with yellow inline highlights and a yellow legend swatch. Line numbers and blank alignment cells preserve source positions; a shared scroll region keeps both sides synchronized. The toolbar contains `Collapse unchanged` (off by default) and `Wrap lines` (on by default). Difference counts and navigation controls are intentionally omitted; the comparison utility returns aligned rows without calculating difference blocks. More than two input slots expose left/right pair selectors; choosing the opposite text swaps the pair. CRLF, CR, and LF are treated as equivalent line endings; all other whitespace, field order, and delimiters are compared literally, and actual SOH is displayed as `␁` without changing the comparison source. A final newline remains visible as an empty last line.

Collapsing retains two unchanged lines beside edits and replaces longer unchanged runs with a `Show … unchanged lines` row when at least three lines can be hidden. Each changed, added, or removed line stays fully visible with its character highlights, including all wrapped screen lines. No character-level folding controls exist. Soft wrapping does not create source lines, so logs where every physical line changes have no fold rows. Individual whole-line sections expand/collapse together across both panes. Source edits reset individual expansions; switching the compared pair resets view controls. Turning the global control off restores all lines, and turning it back on collapses all eligible sections again. Folding only changes presentation and preserves original inputs and line numbers.

## Visual Board Data Flow
1. `ImportPanel` accepts pasted text or one or more uncompressed `.log`, `.txt`, and `.fix` files; browser memory is the practical limit.
2. Compressed extensions (`bz2`, `gz`, `zip`, `7z`, `rar`, `xz`, `zst`) are rejected with instructions to decompress locally. No decompression dependency is included.
3. The Web Worker reads the `File` or pasted text, parses log-prefix metadata and FIX pairs, and keeps the analysis source plus message character offsets. A pasted pretty/JSON export is normalized into one FIX message per line while its exact original paste is retained for raw copy-all.
4. The main thread receives compact records without raw log lines.
5. Selecting a message asks the worker for the original line and duplicate-preserving pairs on demand.
6. The initial parse collects the complete set of numeric tags encountered without retaining another message copy. Field projection, count investigation, or value hints ask the worker for arbitrary numeric tags. Each newly requested tag is scanned from retained local source once and indexed by message. Flow projection returns ordered values only when requested; Field Counts stay in the worker and return compact totals. Value hints count each distinct value at most once per message and return the complete distinct set for the current scope.
7. Copy asks the worker to format either the complete pasted source or the selected detected group's message offsets. File sources require a selected group and cannot be copied wholesale. Every generated format can be pasted back: raw, pipe, and SOH parse directly; pretty/bracketed and JSON are reconstructed locally with field order and duplicates preserved.
8. Clear, cancel, route teardown, reload, or tab close terminates the worker and releases its dataset.

## Visual Board Parsing and Correlation
- Prefix parsing extracts timestamp, incoming/outgoing direction, and common `sender->target:qualifier` session labels. Message admission recognizes versioned FIX-family BeginString values rather than requiring the literal `8=FIX.` prefix.
- A consistent delimiter is inferred per FIX message from the `BeginString(8)` → `BodyLength(9)` boundary. Arbitrary single- or multi-character separators are supported, including control characters, punctuation, text/Unicode markers, and numeric markers. Headerless input uses repeated-boundary inference; whitespace-separated fields retain a best-effort fallback.
- Tokenization only treats the detected delimiter as a boundary when it is immediately followed by a numeric `tag=`, preserving spaces, equals signs, and delimiter-like punctuation inside field values.
- Duplicate FIX fields are preserved in ordered detail pairs; an index also exposes convenient first values.
- Correlation uses disjoint-set graph merging with exact IDs only:
  - `ClOrdID(11)` / `OrigClOrdID(41)`
  - `OrderID(37)`
  - `QuoteReqID(131)`
  - `QuoteID(117)`
  - session-scoped `MDReqID(262)`
- Bridge messages can join RFQ → Quote → Order → Execution lifecycles across sessions.
- Broad attributes such as symbol, currency, or timestamps never merge groups.
- Detected group types are `rfq-order`, `rfq`, `order`, `market-data`, and `session`.

## Overview, Flow, and Filtering
- Capture lag is `log prefix timestamp - SendingTime(52)` and is not presented as request/response latency.
- Matched round-trip latency pairs `New Order Single (D)` with `Execution Report (8)` by exact `ClOrdID(11)` in session context.
- The result toolbar exposes Overview, Flow, and Field Counts. The separate Latency, Quotes & Prices, Orders, and Diagnostics tabs remain removed; per-message capture/round-trip/gap latency remains selectable inside Flow.
- Overview keeps dataset, group, session, message-type, time-span, and Flow latency-count summaries without constructing removed table/diagnostic payloads in the worker.
- The sequence board uses fixed-row windowing implemented in project code; no virtualization package was added. Scroll events update React only when the overscanned start/end row window changes, and rows use static absolute positions instead of transformed compositor layers.
- Long pretty-message tables and the sequence board avoid hover-state repainting inside moving scroll surfaces. Their scroll regions use layout/paint containment, and message rows remain statically positioned so browser compositing work stays bounded.
- The sequence board can project up to six FIX tags as separate compact columns. Repeated tags from repeating groups remain in message order within their column, and the board scrolls horizontally when the selected fields exceed the viewport.
- Flow full-screen mode covers the app chrome and group explorer, keeps the active toolbar/filters and projected fields, lets the sequence board consume the remaining viewport, and preserves message-drawer behavior above the focused workspace.
- The loaded desktop dashboard uses a viewport-bounded two-column grid beneath the sticky app header. The removed source-summary card no longer consumes vertical space; group cards and Flow content scroll independently while search, pagination, tabs, filters, and page position remain fixed.
- Flow renders stable local/counterparty positions: outgoing messages point right (`local → remote`) and incoming messages point left (`local ← remote`) instead of swapping endpoints while always pointing right.
- The detected-groups explorer renders groups in pages, defaults to 25 rows, and supports 10, 25, 50, or 100 groups per page. Search and type filters reset it to the first page.
- Flow filters include an inclusive UTC time-of-day range with second/millisecond precision, open-ended bounds, and overnight ranges when the start is later than the end.
- Field Counts accepts any positive numeric tag and an optional case-insensitive value fragment. A value containing `*` instead uses case-insensitive full-value wildcard matching, so `USD/*`, `*/USD`, and `*/USD*` match the corresponding symbol shapes. Tag entry lists every tag found in the loaded messages and enriches known tags with dictionary names; exact numeric tags list every distinct actual value in the current all/group/ungrouped scope with dictionary enum labels and matching-message counts. Both menus use fixed-height windowing so the complete lists remain scrollable without mounting every row. Users can create independent comparison tabs whose label and count badges stay visible together (for example `35=R` and `35=AG`). Within a tab, blank values mean “field exists,” every repeated occurrence is searched, and each row reports standalone and cumulative AND counts. Investigations do not modify Flow.
- The loaded-dataset toolbar copies an entire pasted dataset or one selected detected group as exact original text, normalized pipe or SOH FIX, readable bracketed fields, or duplicate-preserving JSON. For uploaded files, the control stays disabled until a detected group is selected and copies only that group's original source lines or parsed messages.

## Local-Only Security Contract
- Application source must not call `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, or `navigator.sendBeacon`.
- No analytics, telemetry, remote fonts/assets, CDN resources, or CSP reporting endpoints.
- Production CSP includes `connect-src 'none'`, `worker-src 'self' blob:`, `object-src 'none'`, `form-action 'none'`, and `frame-src 'none'`.
- `npm run verify:security` enforces the source/API, dependency, and CSP parts of this contract.
- Imported data is not placed in URL/hash, localStorage, sessionStorage, IndexedDB, cookies, or service-worker caches.
- Clipboard output is created only after the user explicitly chooses a format; it remains a browser-local action and is never sent by application code.
- The static host and browser extensions are outside the app's trust boundary; README describes this limitation explicitly.

## Known Risks and Gotchas
- Parser behavior is intentionally tolerant; malformed or vendor-specific text can yield partial messages or skipped-line diagnostics.
- Exact-ID correlation avoids false positives but cannot infer a lifecycle when the producer omits all supported bridge identifiers.
- `MDReqID(262)` is session-scoped; incorrect/missing session prefixes reduce correlation quality.
- Round-trip matching currently covers `D → 8`, not every possible FIX request/response pair.
- A large input can consume several times its file size in transient browser/worker memory. There is no fixed application ceiling, so the browser or operating system may still terminate analysis when device memory is exhausted. Keep compact records free of raw lines and avoid unnecessary source copies.
- Each distinct field tag requested by projection or count investigation adds an in-memory per-message index until the dataset is cleared; cached tags trade memory for faster reuse.
- Repeating-group diff alignment uses delimiter identity plus occurrence order. Groups with duplicate delimiter values but no stable additional identity can still be ambiguous; explicit instance headers make additional/missing occurrences visible.
- Text diff bounds Myers search history/work and replacement-line alignment. Large unrelated blocks can fall back to positional replacement highlighting while preserving every source character; minimal alignment is best effort in that case. The unfolded comparison table renders all aligned lines, so very large raw pastes remain subject to browser rendering/memory limits even though folding reduces visible content.
- `src/App.css` is unused Vite starter CSS.
- Browser compositor flicker has no meaningful Node-only regression seam; retain the long repeating-group browser stress check when changing drawer/table/scroll CSS.
